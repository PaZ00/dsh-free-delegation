# dsh-free-delegation

Host-бандл профиля `desktop`: обязательное делегирование субагентам для
корневой облачной модели.

## Зачем

Профиль работает на облачной `aiai-by/deepseek-v4.1-flash`. У пресетов
`standard`, `cordis` и `ptc` строка `tool-subagent` не задавала `agentOptions`,
поэтому ребёнок наследовал маршрут родителя — то есть платную модель. Плюс
ничто не обязывало корневую модель делегировать: она выполняла работу сама.

Бандл закрывает вторую половину задачи — принуждение. Первую половину
(бесплатный маршрут детей) задаёт `agentOptions` в пресетах профиля.

## Что делает

Регистрирует секцию `systemPrompt` с текстом-функцией. Секция выдаёт мандат
только корневому агенту, только в двух режимах — «стандартный» (`standard`) и
«руководитель» (`lead`) — и не выдаёт его детям, локальным корням и остальным
пресетам (`cordis`, `ptc`, `minimal`). Подробности и обоснование — в
[docs/DETAIL.md](docs/DETAIL.md).

## Два исполнителя

По умолчанию в мандате объявлены **два** маршрута:

| Роль | Маршрут | Когда |
|---|---|---|
| Дешёвая, по умолчанию | `aiai-by/solar-mini-4-5` | чтение, поиск, рутина, короткая однозначная спецификация, тесты по готовому списку |
| Вторая, на подъём | `aiai-by/hy4-flash` | сложная логика, изображения, контекст > 524K, нечёткая задача, зацикливание, два провала дешёвой |

Правило переключения — по сложности задачи, а не по цене за токен: замеры
показали, что на сложной задаче дешёвая модель делает вдвое больше запросов и
выходит дороже второй (0.01708 против 0.01682 BYN при 180 с против 116 с).
Чтобы вернуть жёсткое правило «РОВНО ОДИН исполнитель», уберите поле
`escalation` из `cordis.patch.yml` или поставьте ему `null`.

Жёсткое принуждение (`tools.guard`) не зависит от этого поля: пока корень не
запустил хотя бы одного субагента, рабочие инструменты отвечают отказом.

## Проверки

```
node test/mandate.test.mjs      # 43 проверки
node test/enforcement.test.mjs  # 33 проверки
node test/mutation-check.mjs    # 10 мутантов, все убиты
```

Мандат также требует дробить работу: не отдавать субагенту сложную задачу
целиком, а выдавать по одному мелкому проверяемому шагу, контролировать каждый
шаг и отвечать за итог самому — исполнитель слабее корневой модели. Приёмку
предписано строить на своём корпусе входов и мутационной проверке, а не на
отчёте исполнителя: в мандат включён разобранный случай с `ъ`/`ь`, где дешёвая
модель дала `"pod-ezd"` при зелёных собственных тестах.

## Почему отдельный плагин, а не persona пресета

Persona — статическая строка: она не видит ни глубину агента, ни его провайдера.
Безусловный приказ делегировать сломал бы детей: они идут с глубиной 1 при
хостовом `maxDepth` 1 и делегировать не могут.

## Ограничения

- Мандат — инструкция в промпте, а не запрет. Технически корневой агент может
  вызвать инструмент напрямую.
- Бесплатные маршруты подчиняются лимитам провайдера и региональным
  ограничениям. Мандат требует сверять доступность через `list_subagent_models`,
  но маршрут может отказать уже в ходе задачи.
